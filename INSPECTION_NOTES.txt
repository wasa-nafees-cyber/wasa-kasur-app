WASA Officer App - inspection and patch notes

Changes made:
1. Management role in admin-panel.html is restricted to the Dashboard screen. Non-dashboard navigation is hidden and attempts to navigate to other sections return to Dashboard.
2. Admin-only checks were added to account approval/rejection, officer management, consumer editing, activity deletion/editing, form-builder changes, corrections, duplicates, bulk consumer loading and related administrative actions.
3. Management dashboard defaults to Today for activity and recovery filters.
4. Fixed dashboard recovery total so it uses the Recovery date filter instead of incorrectly reusing the Activities date filter.
5. Removed duplicate assignment of the authenticated user object in the admin login flow.

Important security limitation:
These are client-side UI/JavaScript protections. The ZIP did not include Firebase Firestore Security Rules or a trusted server-side authorization layer. The current app performs its own phone/password check against Firestore documents and includes hard-coded fallback/super-admin credentials in client code. A user with browser developer tools may bypass client-side checks, and credentials stored/read by the client are not secure. Do not treat this as production-secure until authentication is moved to Firebase Authentication (or a trusted backend) and Firestore Security Rules enforce role-based permissions. Also rotate exposed credentials and remove hard-coded default credentials before production deployment.

Validation performed:
- JavaScript syntax checked with Node.js --check for both HTML apps' inline scripts.
- This is a static code inspection; no live Firebase credentials, production database, browser UI, or real device workflow was available for end-to-end testing. Therefore a guarantee of zero bugs cannot honestly be made.
